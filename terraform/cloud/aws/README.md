# Terraform — Secure n-tier AWS Infrastructure

Infrastructure-as-Code for the whole platform: VPC, security groups, ALB + WAF,
EC2 ASG, ECR, RDS + Secrets Manager, CloudWatch monitoring, optional EKS and
Jenkins. Everything is driven by the repo's `stack.json` manifest (services,
database engine/version/port) and the environment tfvars.

## Layout

```
terraform/
├── provider.tf     provider config (region + default tags)
├── versions.tf     terraform + provider version pins
├── backend.tf      remote state (S3 + DynamoDB lock)
├── main.tf         wires every module together + CloudTrail + CI/CD IAM policy
├── variables.tf    root variables (all configurable)
├── locals.tf       derived values (AZs, stack.json decode)
├── outputs.tf      useful outputs (URL, db host, secret ARN, EKS/Jenkins)
├── modules/
│   ├── vpc/        VPC, subnets, IGW, NAT, route tables, NACLs, flow logs
│   ├── security/   ALB / app / DB security groups (least privilege)
│   ├── alb/        ALB + listeners + WAF web ACL
│   ├── compute/    launch template, IAM instance role, ASG, scaling policy
│   ├── ecr/        ECR repos (scan, encryption, lifecycle, repo policy)
│   ├── database/   RDS (private, encrypted, backups) + Secrets Manager
│   ├── monitoring/ SNS + CloudWatch alarms + dashboard
│   ├── eks/        optional EKS cluster + managed node group
│   └── jenkins/    optional self-hosted Jenkins controller on EC2
├── environments/
│   ├── dev/        dev tfvars + backend.hcl
│   └── prod/       prod tfvars + backend.hcl
└── scripts/
    └── bootstrap-state.sh   one-time S3 bucket + DynamoDB table creation
```

## Prerequisites

- Terraform >= 1.5 (see `versions.tf`)
- AWS CLI v2, configured credentials (or `AWS_PROFILE`)
- `jq` on PATH (the manifests and scripts use it)

## Validate

```bash
terraform fmt -check -recursive
terraform init -backend=false -input=false   # no AWS needed
terraform validate
```

## Plan

```bash
terraform init -backend-config="environments/dev/backend.hcl" -reconfigure
terraform plan -var-file="environments/dev/terraform.tfvars"
```

## Apply

```bash
terraform apply -var-file="environments/dev/terraform.tfvars"
```

## Destroy (dev only)

```bash
terraform destroy -var-file="environments/dev/terraform.tfvars"
```

> Production uses `deletion_protection = true` and `skip_final_snapshot = false`
> so `terraform destroy` will refuse to run — that is intentional. Remove the
> protection explicitly before tearing down prod.

## Remote state

State lives in S3 (encrypted, versioned) and locks in DynamoDB (`terraform-locks`).
The bucket/table are created once by `scripts/bootstrap-state.sh` and referenced
per environment in `environments/<env>/backend.hcl`. Secrets (`random_password`
outputs) are written into state — that is why the state bucket must be private
and encrypted.

## Security model

- App and DB instances live in private subnets; only the ALB is public.
- ALB SG allows 80/443 from the internet; app SG allows only the ALB; DB SG
  allows only the app SG (no `0.0.0.0/0`).
- SSH is not exposed — use AWS Systems Manager Session Manager (the instance
  role includes `AmazonSSMManagedInstanceCore`).
- DB credentials are generated by Terraform and stored only in Secrets Manager;
  nothing sensitive is hard-coded or committed.
- IMDSv2 is required on the EC2 launch template; root EBS volumes are encrypted.
- WAF managed rules (Common, SQLi, IP reputation) protect the ALB.

## Cost

Cheap by default (t3.micro, single NAT, db.t3.micro, single-AZ). Flip the
variables in `environments/prod/terraform.tfvars` (multi-AZ, 2 NATs, detailed
monitoring, enhanced RDS monitoring, deletion protection) for a production
profile. See `docs/cost-guide.md` for a full breakdown.
