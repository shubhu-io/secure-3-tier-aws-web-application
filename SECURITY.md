# Security Policy

This project is a **production-inspired learning platform**. The infrastructure
is hardened for a real deployment, but you must adapt it to your own
compliance, threat model, and cost requirements before production use.

## Reporting a Vulnerability

If you find a security issue in the code, configuration, or documentation,
please **do not open a public issue**. Report it privately to the repository
owner by email or GitHub Security Advisory.

Please include:

- A description of the issue and its impact.
- Steps to reproduce.
- Affected files/resources.
- A suggested fix if you have one.

We aim to acknowledge reports within 48 hours and to provide a fix timeline
within 7 days.

## Security Model

| Layer        | Control used in this project                                    |
| ------------ | --------------------------------------------------------------- |
| Perimeter    | AWS WAF (managed rule sets) in front of the ALB                  |
| Transport    | TLS 1.2+ via ACM certificate on the ALB, HTTP→HTTPS redirect     |
| Network      | Private subnets for app + DB, no public access to RDS            |
| Compute      | No public SSH (Systems Manager Session Manager instead)          |
| Firewall     | Layered security groups: ALB → App → DB                         |
| Identity     | IAM roles with least privilege, no long-lived keys on EC2        |
| Secrets      | AWS Secrets Manager for DB credentials, no secrets in repo       |
| Data at rest | RDS encryption, ECR image encryption, optional KMS CMK            |
| Auditing     | CloudTrail, VPC Flow Logs, ALB access logs (optional)            |

## Secrets Handling

- All `.tfvars` files are gitignored. Only `.example` files are committed.
- Database passwords are generated by Terraform and stored in Secrets Manager,
  never written to state files in plaintext that gets committed (use a remote
  state backend that supports encryption).
- CI/CD uses GitHub Actions **secrets** (encrypted at rest), not repo files.

## Dependency Scanning

- Base images: minimal (Alpine) with `non-root` runtime users.
- Trivy scans Docker images in CI; the pipeline **fails** on CRITICAL or HIGH
  vulnerabilities.
- Node dependencies are scanned by `npm audit` during CI.
